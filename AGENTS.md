# Lakshmi Portfolio — Project Instructions

## Core Rule

This is a highly customized personal portfolio website.

Do NOT invent, assume, add, remove, simplify, redesign, paraphrase, or replace any functionality, content, interaction, or design decision unless I explicitly request it.

The user's portfolio specification is the source of truth.

## Source of Truth

The complete website specification is stored in:

docs/PORTFOLIO_SPEC.md

Before implementing any feature, read the relevant section of PORTFOLIO_SPEC.md.

Do not rely on memory from previous OpenCode sessions.

## Implementation Rules

- Inspect the existing code before making changes.
- Preserve working functionality unless the requested task requires changing it.
- Implement only the requested phase/task.
- Do not modify unrelated sections.
- Do not create placeholder personal information when actual information is provided.
- Do not invent missing social links, achievements, projects, events, text, or personal details.
- Do not add extra animations, sections, decorations, interactions, components, or features simply because they seem like a good idea.
- Do not replace the chosen visual direction with a generic portfolio design.
- Keep the website visually intentional and faithful to the specification.
- Reuse the existing project structure and dependencies where practical.
- Do not introduce a new library unless it is genuinely required for the requested feature.

## Content Rules

When the specification says "exact content", use it exactly.

Do not:

- rewrite it
- paraphrase it
- shorten it
- expand it
- correct it
- add marketing language

If information is explicitly missing, leave it missing rather than inventing it.

## Design Rules

The final website must maintain the specified:

- light beige background
- blue accents
- pink accents
- Player Mode typography
- Recruiter Mode typography

Do not introduce unrelated colour palettes.

## Verification

After implementation:

1. Run the appropriate build/type-check/lint commands.
2. Fix errors caused by your changes.
3. Inspect the resulting implementation.
4. Clearly report:
   - what you changed
   - what files changed
   - what was verified
   - anything that remains incomplete

Never claim something works without actually verifying it.

## Important

Do not build the entire website in one step.

Work in small phases.

Wait for the user's instruction before moving to the next phase.
